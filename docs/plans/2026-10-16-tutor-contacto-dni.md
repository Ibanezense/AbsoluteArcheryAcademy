# Corrección del guardado del tutor y DNI para boletas

Evidencia: los registros de producción muestran `update:find-or-create-guardian` rechazando el correo porque ya pertenece al acceso del alumno. La ficha además pasa un objeto de error a `new Error`, generando `[object Object]`.

Separar los datos del responsable para boletas de la cuenta de acceso: añadir `students.guardian_contact` opcional con nombre, email, teléfono y DNI. El contacto puede compartir correo con el alumno y no requiere acceso propio. Mantener perfiles, roles, códigos y relaciones existentes; cuando aún no existe contacto guardado, mostrar los datos del perfil de tutor vinculado.

La ficha guarda este contacto mediante la API administrativa existente, sin interpretar sus campos como una solicitud de crear una cuenta. Añadir DNI de 8 dígitos, conservando ceros iniciales. El formulario de alta/edición muestra los datos de contacto siempre y distingue el email de acceso si se solicita cuenta de tutor. Omitir el nuevo campo conserva el contacto previamente guardado.

Extraer el texto de errores estructurados para mostrar el mensaje real. Verificar contacto con el mismo email que el alumno, persistencia y recarga del DNI, validación antes de escribir, ausencia de nuevas cuentas/permisos, compatibilidad con perfiles de tutor anteriores, pruebas, lint y build. Usar únicamente alumnos sintéticos en las pruebas de escritura.

Verificado: 131 archivos y 683 pruebas aprobadas, lint, TypeScript y compilación correctos. Migración aplicada `20261016141747_student_guardian_contact.sql`. El caso real reproducido con un alumno sintético guardó contacto con el mismo correo que el alumno y DNI con cero inicial; conservó el perfil, rol y código de acceso del alumno y no creó acceso de tutor. Peticiones con DNI inválido se rechazaron antes de escribir, un cliente antiguo que omite el campo conservó el contacto y un usuario alumno recibió 403. En navegador se guardó y recargó `00123456`, se comprobó el aviso de ocho dígitos y se guardó desde ambos formularios. La revisión detectó y se corrigió la posible sustitución de identidad de una cuenta vinculada en el editor; ahora un helper probado conserva nombre/email/teléfono/DNI del acceso existente aunque el responsable de boleta sea distinto. Alumno y acceso QA retirados al finalizar. Interfaz disponible localmente, pendiente de publicación.
